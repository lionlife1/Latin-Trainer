# LatinIQ

Latin grammar and vocabulary trainer for TSJCL exam prep. TypeScript, React 18, Vite, Vitest,
Playwright, Supabase (SQL migrations, RLS, Deno edge functions). See `README.md` for the full layout.

## Commands

```bash
npm run dev                              # solo mode, http://localhost:5173
npm test                                 # Vitest: src/, scripts/, supabase/functions/_shared
npx vitest run path/to/file.test.ts      # one test file
npx tsc -b                               # type check
npm run build                            # tsc -b && vite build
PW_CHANNEL=chrome npx playwright test    # e2e; bundled Chromium is not installed on this machine
npm run test:db                          # SQL/RLS tests; needs DATABASE_URL or Postgres 16 via PGBIN
npm run seed                             # regenerate supabase/seed.sql, seed-lexicon.sql, *.generated.ts
```

## Notes

- `src/content/modules.ts` is about 6,500 lines. Search for a module or question id and read that
  region; don't read the whole file.
- `src/content/*.generated.ts` and `supabase/seed*.sql` are generated by `npm run seed` from
  `scripts/lexicon/`. Change the generator, not the output.
- Applied migrations are never edited; add a new file in `supabase/migrations/`.
- Specs and plans live in `docs/superpowers/specs/` and `docs/superpowers/plans/`. Finished ones move to
  `docs/superpowers/archive/`. `docs/OPEN-WORK.md` lists what is still outstanding.

## Delegation

The main session does design, debugging and review. Routine work goes to the agents in `.claude/agents/`.

| Work | Goes to |
|---|---|
| A concrete, already-designed coding task (a plan task; engine, UI, scripts, SQL) | `implementer` (Sonnet, medium) |
| Text students read: module questions, hints, explanations, lessons, UI copy | `latin-content-writer` (Opus, high) |
| Running `npm test`, `tsc -b`, the build, Playwright or `test:db` | `verifier` (Haiku) |
| Finding where something lives, or anything inside the large content files | `Explore` (Haiku) |

Stays in the main session:

- Specs, plans, and any decision about design or scope.
- Debugging: when the verifier reports a failure or an implementer gets stuck, diagnose it here, then
  hand back a concrete fix if it is routine.
- Review of every diff an agent produces, including checking the Latin in new content, before it is
  committed.
- Commits. Agents leave their changes in the working tree; the main session commits after review.

When delegating, give the agent the task text, the files involved and what "done" looks like. It
starts with none of this conversation. Read the diff an agent produced rather than trusting its
report, and run the verifier before calling work complete.
