# Morphology Engine and Practice → Forms Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One morphology engine in `src/lib/morph/` that makes and parses every verb, noun, adjective and pronoun form a school Latin course drills, and a Practice → **Forms** drill built on it.

**Architecture:** The engine is a set of pure functions over small word records: `Verb` (the existing conjugator shape), plus new `Noun`, `Adjective` and `Pronoun` records. Each kind exposes `xxxCells(word)` (the cells the word really has) and `xxxForms(word, cell): string[]` (the main form first, then accepted variants; `[]` for a cell the word lacks). `src/lib/conjugator.ts` keeps its exports, and `generateSubjunctiveForm` becomes a thin wrapper over the engine, so Endless Train is unchanged. Core nouns and adjectives are generated by `npm run seed` from the Whitaker stems, the same way verbs already are. Forms questions are ordinary `typein`/`mc` `DrillQuestion`s run by `DrillSession`.

**Tech Stack:** TypeScript, React 18, react-router 6, Vitest + Testing Library, Playwright, `tsx` scripts.

**Spec:** `docs/superpowers/specs/2026-11-06-forms-vocab-modules-design.md` (section A, plus the global constraints). Background: `docs/trainer-core-verbs-followups.md`, `docs/teacher-tools/plan.md` §2 "Morphology engine", and the earlier plan `docs/superpowers/plans/2026-11-04-trainer-core-verbs.md`.

## Global Constraints

Copied verbatim from the spec. Every task's requirements include this section.

- **No database schema changes and no new migrations.** Nothing here needs the Supabase backend; everything
  works in solo mode, logged out, offline. (Plan C changes `supabase/seed.sql` through `npm run seed`, which
  is content, not schema.)
- **Reuse the existing question types and UI.** Every generated or authored question is a `DrillQuestion`
  (`typein` or `mc`, `src/lib/types.ts`) and runs in the existing `DrillSession` (`src/features/drill/`).
  No new item types, no grid UI, no renderer registry (those are teacher-tools Phase 2).
- **Match the redesign's visual style**: light, Quizlet-calm, sans-serif, no emoji, phones first (375px, no
  horizontal scroll). Reuse existing CSS classes and tokens.
- **Practice is local-first**: progress lives in `localStorage` through the existing session log
  (`src/features/practice/sessionLog.ts`) and syncs through `practice_sessions` only where that already
  happens. Every storage read/write tolerates missing or corrupt data.
- **Generated data is built by scripts, never edited by hand.** Data fixes go in `scripts/lexicon/*`, and
  `npm run seed` regenerates `src/content/*.generated.ts`.
- **Macrons**: generated forms have no macrons (the Whitaker stems have none), and grading already ignores
  macrons and case (`src/lib/grading.ts`). Hand-written text for students (Plan C) uses macrons as the
  existing modules do.
- **Tests**: Vitest for logic and components, written test-first. Keep `npm test`, `npx tsc -b` and
  `npx playwright test` (solo) green. Update tests whose copy or counts legitimately change; never delete a
  test to make a change pass.
- **Student-facing prose** (module descriptions, explanations, hints, UI copy longer than a label) is
  written by the most capable model, in plain direct English, with few em dashes.

Plan-wide conventions:

- Commit messages end with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `practice_sessions.kind` has a server check constraint `kind in ('module', 'endless', 'import')`
  (`supabase/migrations/20261101152412_practice_sessions.sql`). A `forms` row must never be pushed: one bad
  row fails the whole upsert batch, and every later sync retries it forever. Task 12 adds an allowlist of
  server kinds in the sync code; Plan B relies on it for its `vocab` kind.
- All forms are lower case, `j` is written `i`, no macrons, at most one space (two-word forms such as
  `amatus sum`, `amatum iri`, `non vis`).
- Forms with a participle are given in the **masculine** (`amatus est`, `amati sunt`), as Endless does today.
  Task 11 adds feminine and neuter variants to accepted *answers* only.
- Test-only seeded RNG: use `seededRng` from `src/lib/shuffle.ts`.

## Review Focus

1. **Ambiguous forms in Identify.** *puellae*, *regis*, *amare*, *se*: a valid parse must never be offered as a
   wrong choice, and the explanation names every valid parse. Task 11 test `never offers another valid parse
   as a distractor`.
2. **Forms sessions and sync.** A signed-in student finishes a Forms session; the next sync must push the
   other sessions and leave the `forms` row local and unsynced, and keep doing so on every later sync.
   Task 12 test `never pushes a kind the server rejects`.
3. **Settings that match nothing** (Pronouns only with no style; Verbs: Deponent + Passive only + Imperative
   + Pluperfect). The generator returns `null` without looping forever, and Start is disabled with a message.
   Task 11 test `returns null when no cell matches`; Task 13 test `disables Start when nothing matches`.
4. **Cells a word lacks** (*vīs* gen. sg., *possum* imperative, *multus* comparative masc. sg., the passive
   of an intransitive, *sum* gerund). They are never asked, and no answer is ever empty. Task 11 test
   `generates 600 well-formed questions across every kind`, plus the pool smoke tests in Tasks 2, 6 and 8.
5. **Corrupt or old local data.** A garbage `latiniq_forms_settings` value or a malformed session entry
   must fall back to defaults instead of crashing Practice home or the Forms screen. Task 12 test `drops
   malformed entries`; Task 13 test `falls back to defaults for corrupt settings`.

**Interfaces:**
- Produces, in `src/lib/morph/types.ts`:

  ```ts
  export type GrammaticalNumber = 'singular' | 'plural';
  export type Person = 1 | 2 | 3;
  export type VerbTense = 'present' | 'imperfect' | 'future' | 'perfect' | 'pluperfect' | 'futurePerfect';
  export type Case = 'nominative' | 'genitive' | 'dative' | 'accusative' | 'ablative' | 'vocative';
  export type Gender = 'm' | 'f' | 'n';
  export type Degree = 'positive' | 'comparative' | 'superlative';
  export interface Verb { /* moved verbatim from conjugator.ts, same fields and comments */ }
  export type VerbCell =
    | { mood: 'indicative'; tense: VerbTense; voice: Voice; person: Person; number: GrammaticalNumber }
    | { mood: 'subjunctive'; tense: 'present' | 'imperfect' | 'perfect' | 'pluperfect'; voice: Voice; person: Person; number: GrammaticalNumber }
    | { mood: 'imperative'; tense: 'present' | 'future'; voice: Voice; person: 2 | 3; number: GrammaticalNumber }
    | { mood: 'infinitive'; tense: 'present' | 'perfect' | 'future'; voice: Voice }
    | { mood: 'participle'; tense: 'present' | 'perfect' | 'future'; voice: Voice }
    | { mood: 'gerund'; case: 'genitive' | 'dative' | 'accusative' | 'ablative' };
  ```
  The gerundive is the participle cell `{ tense: 'future', voice: 'passive' }`.
- Produces, in `src/lib/morph/verbs.ts`:
  ```ts
  export const ALL_VERB_CELLS: readonly VerbCell[];   // 143 cells, order below
  export function hasVerbCell(verb: Verb, cell: VerbCell): boolean;
  export function verbCells(verb: Verb): VerbCell[];  // ALL_VERB_CELLS.filter(c => hasVerbCell(verb, c))
  export function verbForms(verb: Verb, cell: VerbCell): string[]; // [] when !hasVerbCell
  ```
  `ALL_VERB_CELLS` order: indicative (6 tenses × active, passive × 1sg…3pl = 72), subjunctive (4 × 2 × 6 = 48),
  imperative (present active 2sg, 2pl; present passive 2sg, 2pl; future active 2sg, 3sg, 2pl, 3pl = 8),
  infinitive (present, perfect, future × active, passive = 6), participle (present active, perfect passive,
  perfect active, future active, future passive = 5), gerund (genitive, dative, accusative, ablative = 4).
- `conjugator.ts` keeps exporting `Verb`, `Voice`, `GrammaticalNumber`, `Person` (`export type { … } from './morph/types'`)
  and its own `Tense`. Nothing else in `conjugator.ts` changes in this task. `verbs.generated.ts` still imports
  `type { Verb } from '../lib/conjugator'`.

**Cell rules for this task** (non-irregular verbs only; `verbForms` returns `[]` for any `irregular` verb until Task 2):

| Cell | Claimed when |
|---|---|
| finite active, imperative present active, infinitive present/perfect active, gerund | always |
| finite passive, imperative present passive, infinitive present passive | `!deponent && !noPassive` |
| infinitive perfect passive, participle perfect passive, infinitive future passive (`amatum iri`) | `!deponent && !noPassive && ppp` |
| participle perfect active | `deponent` |
| participle present active | always |
| participle future active, infinitive future active | a future stem exists (below) |
| participle future passive (gerundive) | `deponent \|\| !noPassive` |
| imperative future active | `!deponent` |

- Deponents claim only `voice: 'active'` finite, imperative and infinitive cells and are built with passive
  endings, as the conjugator does now. Their perfect system uses `verb.perf` as the participle stem
  (`hortat` → `hortatus sum`).
- Future active participle stem: `FUT_PART_STEM[verb.inf]` (`{ mori: 'moritur', oriri: 'oritur' }`), else
  `verb.perf + 'ur'` for deponents, else `verb.ppp + 'ur'` when `ppp` is set, else none. A `noPassive` verb's
  `ppp` is its future-participle stem (`cad` → `casurus`), so it gets a future participle but no perfect passive one.
- Imperfect subjunctive keeps the conjugator's rule: active `verb.inf + ending`; deponent `verb.impfBase + passive ending`.
- Present 2sg imperative drops the `-e` for `dicere`, `ducere`, `facere` and any conj-3 verb whose `pres` ends in `duc` or `dic`, and conj-3.5 `pres === 'fac'` (`dic`, `duc`, `fac`, `educ`).

**Decisions:**
- *esse* and compounds: `pre` + *sum* forms; when `pre` ends in `pro`, insert `d` before a form starting with `e` (`prodes`, `prodest`, `prodestis`, `proderam`, `prodero`, `prodesse`). Perfect system from `verb.perf`. Future participle `verb.perf + 'turus'` (`futurus`, `afuturus`). Claims: active finite, imperative present 2sg/2pl and future, infinitives present/perfect/future active, future participle. No present participle, gerund or gerundive.
- *posse*: finite active (no future imperative/imperative at all), infinitives present and perfect. Nothing else.
- *ire* and compounds: present stem forms `pre` + `eo, is, it, imus, itis, eunt`; `ibam`; `ibo`; passive (only when `!noPassive`) `eor, iris, itur, imur, imini, euntur`, `ibar`, `ibor, iberis, ibitur, ibimur, ibimini, ibuntur`. Present participle `pre + 'iens'`; gerund `pre + 'eundi'` etc.; gerundive `pre + 'eundus'` only when `!noPassive`. **Perfect-system variants:** for a primary form `pre + 'iv' + end`, add `pre + 'i' + end`, and when `end` starts with `is`, also `pre + 'i' + end.slice(1)`. The replacement only ever touches the text after `pre` (follow-up "replace only after the prefix").
- *ferre* and compounds: A&G §200 (`fers`, `fert`, `fertis`; passive `ferris`, `fertur`; imperative `fer`, `ferte`, future `ferto`, `fertote`, `ferunto`; imperfect subjunctive `ferrem`; present passive infinitive `ferri`).
- *velle / nolle / malle*: hand tables. *velle*: no imperative, participle `volens`. *nolle*: imperative `noli`, `nolite`, future `nolito`, `nolito`, `nolitote`, `nolunto`; participle `nolens`. *malle*: no imperative, no participle. None has a gerund, gerundive or future participle.
- *fieri*: finite active only; perfect system `factus sum` (from `perf: 'fact'`); imperative present `fi`, `fite`; infinitives `fieri`, `factus esse`. No participles, no gerund.
- *esse* future infinitive: `['futurus esse', 'fore']`.

  ```ts
  export type VerbGroup = '1' | '2' | '3' | '3io' | '4' | 'irregular' | 'deponent';
  export type MoodFilter = 'indicative' | 'subjunctive' | 'imperative' | 'infinitive' | 'participle';
  export interface FormsConfig {
    kinds: FormsKind[];
    styles: FormsStyle[];
    verbGroups: VerbGroup[];
    moods: MoodFilter[];
    tenses: VerbTense[];
    voices: Voice[];
    declensions: (1 | 2 | 3 | 4 | 5)[];
    adjTypes: ('12' | '3')[];
    degrees: Degree[];
  }
  export const DEFAULT_FORMS_CONFIG: FormsConfig;
  export interface FormsPools { verbs: Verb[]; nouns: Noun[]; adjectives: Adjective[]; pronouns: readonly Pronoun[] }
  export function defaultFormsPools(): FormsPools;
  export function verbGroup(v: Verb): VerbGroup;
  export function candidateCells(w: MorphWord, config: FormsConfig): Cell[];
  export function eligibleWords(kind: FormsKind, config: FormsConfig, pools: FormsPools): MorphWord[];
  export function formsConfigHasQuestions(config: FormsConfig, pools?: FormsPools): boolean;
  export function pickDistractorCells(w: MorphWord, correct: Cell, valid: Cell[], rng: () => number): Cell[];
  export function makeFormQuestion(w: MorphWord, cell: Cell, rng: () => number): TypeInQuestion;
  export function identifyFormQuestion(w: MorphWord, cell: Cell, rng: () => number): MCQuestion | null;
  export function generateFormsQuestion(config: FormsConfig, rng?: () => number, pools?: FormsPools): DrillQuestion | null;
  export function buildFormsSession(config: FormsConfig, count: number, rng?: () => number, pools?: FormsPools): DrillQuestion[];
  ```

**Decisions:**
- `DEFAULT_FORMS_CONFIG`: `kinds: ['verbs']`, `styles: ['make', 'identify']`, every verb group, `moods: ['indicative', 'subjunctive']`, all six tenses, both voices, all declensions, both adjective types, `degrees: ['positive']`.
- `verbGroup`: `deponent` for `deponent || semiDeponent`; `irregular` for `irregular`; `3io` for conj 3.5; else `String(conj)`.
- `candidateCells` filters `cellsOf(w)`:
  - verbs: `verbGroup(v) ∈ verbGroups`; mood `participle` covers participles **and** the gerund; tense: finite and imperative cells need `tense ∈ tenses`, infinitives and participles need their tense (`present`/`perfect`/`future`) in `tenses`, the gerund ignores tenses; voice: `voice ∈ voices`, except that deponent and semi-deponent verbs and the gerund ignore the voice filter.
  - nouns: `decl ∈ declensions`. Adjectives: `decl ∈ adjTypes` and `degree ∈ degrees`. Pronouns: no filters.
- `eligibleWords` keeps words with at least one candidate cell; memoize per `(config, pools)` with a `WeakMap` keyed by the config object.
- `generateFormsQuestion`: choose uniformly among `config.kinds` with eligible words, then a word, then a cell from `candidateCells`, then a style from `config.styles`. `identify` returning `null` → retry (up to 20 draws total), then fall back to `make`. Returns `null` when `config.styles` is empty or no kind has eligible words. Never loops unbounded.
- `pickDistractorCells`: from `cellsOf(w)`, drop cells whose label equals the label of `correct` or of any `valid` cell; dedupe by label; sort by feature distance to `correct` (number of keys in the union of both `cellFeatures` maps whose values differ), shuffled within equal distance using `rng`; take 3. Returns fewer than 3 only when the word has too few cells.
- `makeFormQuestion`:
  - `type 'typein'`, `badge 'MAKE THE FORM'`
  - `prompt`: `<span class='latin-word' style='font-size: 1.4em;'>${escapeHtml(entryOf(w))}</span><br><span style='font-size: 0.8em; color: var(--text-secondary);'>${cellLabel(w, cell)}</span>`
  - `hint: escapeHtml(meaningOf(w))`
  - `answers`: `formsOf(w, cell)`, plus feminine and neuter variants for verb cells that are finite or are perfect/future infinitives and whose form has a space and does not end in ` iri`: a first word ending `us` adds `a`/`um` versions, ending `i` adds `ae`/`a` versions (`amatus est` → also `amata est`, `amatum est`).
  - `explanation`: `The form is ${answers[0]}.`, and when the engine gave variants, ` Also accepted: ${variants.join(', ')}.` (gender variants are not listed).
  - `id`: `forms_${Date.now()}_${Math.floor(rng() * 1e9)}`.
- `identifyFormQuestion`:
  - `form = formsOf(w, cell)[0]`; `valid = parse(form, [w]).map(a => a.cell)`; `distractors = pickDistractorCells(w, cell, valid, rng)`. Return `null` if fewer than 3.
  - `type 'mc'`, `badge 'IDENTIFY THE FORM'`, `choices` = the 4 labels (correct first; `MCAnswer` shuffles), `correct = cellLabel(w, cell)`.
  - `prompt`: `<span class='latin-word' style='font-size: 1.4em;'>${form}</span><br><span style='font-size: 0.8em; color: var(--text-secondary);'>from ${escapeHtml(entryOf(w))}</span>`; `hint` = meaning.
  - `explanation`: one valid parse → `${form}: ${label}.`; several → `${form} can be any of these: ${labels.join('; ')}.`
- `buildFormsSession`: draw up to `count * 5` times, skip a question whose `type + prompt + (correct | answers[0])` repeats, stop at `count`.
